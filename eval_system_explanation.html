🔍 AI 提示詞評估系統 - 完整流程說明

📊 系統流程圖

1 生成測試資料集
函數：generate_dataset() → 產生 3 個 AWS 測試任務
↓
2 執行測試任務
函數：run_prompt() → 讓 Claude 解決任務
↓
3 雙重評分
① grade_syntax() → 檢查語法是否正確
② grade_by_model() → AI 評估品質
↓
4 計算總分並輸出結果
最終分數 = (語法分數 + AI 評分) / 2

📝 具體範例演示

步驟 1️⃣：生成測試資料集

系統提示：「請生成 3 個 AWS 相關的測試任務...」

Claude 生成的測試任務（範例一）：
{ "task": "創建一個 Lambda 函數的 JSON 配置，設定資料庫連線環境變數", "format": "json", "solution_criteria": "應包含資料庫主機、端口、憑證等環境變數" }

步驟 2️⃣：執行測試任務

系統發送給 Claude：
「請解決以下任務：創建一個 Lambda 函數的 JSON 配置...
⚠️ 只回傳程式碼，不要解釋」
Claude 的輸出：
{ "lambda_function": { "FunctionName": "database-connection-handler", "Runtime": "python3.9", "Environment": { "Variables": { "DB_HOST": "your-database-hostname.rds.amazonaws.com", "DB_PORT": "5432", "DB_NAME": "myappdatabase", "DB_USERNAME": "dbadminuser", "DB_PASSWORD": "{{resolve:secretsmanager:...}}", "DB_SSL_MODE": "require" } }, "Timeout": 30, "MemorySize": 256 } }

步驟 3️⃣：雙重評分系統

評分方式 檢查內容 範例分數
① 語法檢查
(grade_syntax)		 執行 json.loads() 檢查是否為有效 JSON
✅ 成功 → 10 分
❌ 失敗 → 0 分 		10 分
② AI 品質評分
(grade_by_model)		 讓 Claude 分析：
• 優點（strengths）
• 缺點（weaknesses）
• 評分理由（reasoning）
• 最終分數 1-10 		7 分

AI 評分的詳細回饋

{ "strengths": [ "正確使用 Secrets Manager 保護密碼", "包含必要的資料庫連線參數" ], "weaknesses": [ "缺少進階安全設定", "可以更動態化配置" ], "reasoning": "解決方案展示了良好的基礎實踐，但缺少進階的安全性...", "score": 7 }

步驟 4️⃣：計算最終分數

計算公式：
最終分數 = (語法分數 + AI 評分) / 2 = (10 + 7) / 2 = 8.5

📈 完整評估結果

任務 格式 語法分數 AI 評分 最終分數
Lambda JSON 配置 JSON 10 7 8.5
提取 AWS Region 函數 Python 10 6 8.0
驗證 EC2 ID 的 Regex Regex 10 6 8.0
平均分數 8.17

💡 系統的價值

這個評估系統可以用來：
  • 📊 比較不同提示詞的效果（例如：加上「請使用最佳實踐」會提高分數嗎？）
  • 🔄 測試不同模型版本（Haiku vs Sonnet vs Opus）
  • 📈 追蹤模型改進（新版本是否比舊版本更好？）
  • 🎯 自動化測試（每次更新提示詞後自動跑評估）

🔑 核心概念總結

  1. 自動化測試：系統自動生成測試案例、執行、評分
  2. 客觀評估：結合語法檢查（絕對正確性）+ AI 評分（主觀品質）
  3. 可重複執行：可以多次跑同樣的測試，比較結果
  4. 量化結果：用數字（0-10分）來衡量 AI 的表現
